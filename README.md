**A security gate for container builds — scan, sign, ship. Or stop.**

Banks in Luxembourg (and everywhere else) are moving their applications
into Docker and Kubernetes, and the first question any auditor asks is:
how do you prove what is actually running in production? This repository
is a working answer — a GitHub Actions pipeline that refuses to ship any
container image carrying critical vulnerabilities or leaked secrets, and
then cryptographically signs the image that did pass, so nobody can swap
it on the way to the cluster.

## The gate in 30 seconds

| # | stage | tool | blocks the build when |
|---|-------|------|-----------------------|
| 1 | secret leak check | gitleaks (pinned, SHA-256 verified) | a key, token or password appears anywhere in git history |
| 2 | dockerfile lint | hadolint | unsafe image construction in the release build |
| 3 | gate self-test | pytest-style fixtures | the policy engine itself disagrees with its test cases |
| 4 | image scan | trivy | — produces evidence only |
| 5 | image scan | grype | — second opinion, different database |
| 6 | policy as code | `policy_gate.py` | CRITICAL findings, or more HIGH findings than the risk appetite allows |
| 7 | sign + attest | cosign keyless + syft SBOM | signs and attests only what passed 1–6 |

Every tool binary the pipeline uses is downloaded at a pinned version and
verified against a recorded SHA-256 before it is trusted — the pipeline
applies its own medicine to itself.

## Prove the gate actually blocks

CI builds **two** images on every run:

- `app/` — the release candidate (alpine, non-root, pinned deps). The gate
  must return **PASS**, then it is pushed to GHCR and signed.
- `app-vulnerable/` — a deliberately rotten build: end-of-life
  `python:3.8-slim`, `flask==0.12.2`, `jinja2==2.10`, runs as root. The
  gate must return **BLOCK**.

Both legs must be green. If the rotten image ever gets a `PASS`, the
pipeline goes red — a security control that cannot prove it blocks is
decoration. Scan reports for both images are attached as artifacts on
every run, and a sample blocked-build summary lives in
[examples/gate-failure-report.md](examples/gate-failure-report.md).

## Policy as code

Everything the gate enforces lives in one reviewable file:
[policy/scan-policy.yml](policy/scan-policy.yml).

```yaml
gate:
  block:
    - severity: CRITICAL
      fixed: true
      max_allowed: 0
    - severity: HIGH
      fixed: true
      max_allowed: 5
  ignore_unfixed: true
  allowlist: []   # accepted risks, each with a written reason + expiry date
```

Allowlist entries expire. A CVE accepted today stops being accepted on
its expiry date and starts blocking again automatically — no silent
forever-ignores. The self-test covers exactly this, including the
expired-entry case.

## Signing — the part registries can't do for you

Anyone can push a vulnerable image under any name. After the gate passes,
cosign signs the image **keylessly**: GitHub issues the workflow a
short-lived OIDC token, Fulcio turns it into a signing certificate bound
to this repository, and the signature is written to the Rekor transparency
log. No long-lived keys exist to leak. One command answers "was this
image built and approved by this exact pipeline?":

```bash
cosign verify ghcr.io/abdrahmentakrouni/secure-ci-pipeline@sha256:... \
  --certificate-identity-regexp 'github\.com/abdrahmentakrouni/secure-ci-pipeline/' \
  --certificate-oidc-issuer '^https://token.actions.githubusercontent.com$'
```

or simply:

```bash
bash scripts/verify_signature.sh
```

An SPDX SBOM generated by syft is attached as a cosign attestation on the
same digest — the image carries its own ingredient list, cryptographically
bound.

## Nightly drift detection

A verdict is a point-in-time statement. A CVE published tomorrow makes
today's clean image vulnerable. A scheduled workflow re-scans the shipped
image every night against the same policy and re-verifies its signature;
the moment the verdict changes, it opens an issue. Shipped does not mean
forgotten.

## Run the gate locally

```bash
bash scripts/ci_install_tools.sh trivy grype gitleaks hadolint
bash scripts/local_audit.sh
```

## Repository map

```
├── .github/workflows/
│   ├── security-pipeline.yml    # the gate: secrets, lint, scans, policy, signing
│   └── nightly-rescan.yml       # drift detection on the shipped image
├── app/                         # release candidate (must PASS)
├── app-vulnerable/              # deliberately rotten (must BLOCK)
├── policy/scan-policy.yml       # the only file the gate obeys
├── scripts/
│   ├── ci_install_tools.sh      # pinned + SHA-256 verified tool installs
│   ├── policy_gate.py           # the policy engine
│   ├── test_policy_gate.sh      # self-test fixtures (PASS / BLOCK / expiry)
│   ├── local_audit.sh           # full gate, locally
│   └── verify_signature.sh      # one-command image verification
├── docs/                        # architecture, threat model, runbook
└── examples/                    # a real blocked-build summary
```
